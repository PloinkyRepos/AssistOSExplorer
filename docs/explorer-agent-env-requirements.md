# Explorer Agent Environment Requirements

Last updated: 2026-07-12

This document classifies the environment variables used by `AssistOSExplorer/explorer`
and the Ploinky agents that Explorer enables directly or transitively. It answers
one operational question: which values must be supplied by an operator, and which
values are optional, defaulted, generated by Ploinky, produced by Web Publishing,
or injected by the runtime.

## Scope

| Area | Agents |
| --- | --- |
| Explorer dependency stack | `AssistOSExplorer/explorer`, `gitAgent`, `dpuAgent`, `soplangAgent`, `tasksAgent`, `AchillesCLI/achilles-cli`, `basic/webtty`, `webmeetInfra/liveKitServerAgent`, `webmeetInfra/turnServerAgent`, `webmeetStt`, `webmeetAgent`, `multimedia`, `onlyOffice`, `proxies/soul-gateway`, `webAssist`, `basic/web-publishing` |
| Explorer profile policy | Explorer declares only the `default` profile; local, QA, and production launches use that same profile wiring |
| Transitive dependencies | `AchillesCLI/opencodeAgent`, `AchillesCLI/piAgent`, `AchillesCLI/codexAgent`, `AchillesCLI/GPTResearcher`, `proxies/searchAgent`, `proxies/default-local-llm` |
| Missing source | `UmamiAgent/umamiAgent` is enabled by Explorer, but its source was not present in this workspace |

## Summary

| Question | Answer |
| --- | --- |
| Mandatory user-provided values for local/default nginx startup | None found in available source, assuming Ploinky supplies workspace, router, and identity env. Web Publishing's mode normalizer selects `nginx` when `WEB_PUBLISHING_MODE` is unset; the manifest does not declare a mode fallback. |
| Mandatory user-provided values for managed QA/prod public topology | Canonical lowercase `WEB_PUBLISHING_BASE_DOMAIN`, bare unicast/non-loopback IPv4 values for `WEB_PUBLISHING_LIVEKIT_MEDIA_IP` and `WEB_PUBLISHING_TURN_EXTERNAL_IP`, `WEB_PUBLISHING_TLS_EDGE`, a pre-created DNS-only `turn.<base-domain>` A record with no AAAA record, and operator-provisioned TURN TLS material in the remote workspace; token-mode public tunnel startup also requires `WEB_PUBLISHING_CLOUDFLARED_TUNNEL_TOKEN` |
| Values produced by Web Publishing, not supplied directly to Explorer | `ONLYOFFICE_PUBLIC_URL`, `ONLYOFFICE_INTERNAL_URL`, `ONLYOFFICE_CALLBACK_BASE_URL`, `WEBMEET_PUBLIC_LIVEKIT_URL`, `WEBMEET_LIVEKIT_URL`, `WEBMEET_LIVEKIT_NODE_IP`, `WEBMEET_TURN_HOST`, `WEBMEET_TURN_EXTERNAL_IP`, and `WEBMEET_TURN_ALLOWED_PEER_IPS` (plus compatible edge metadata declared by the provider manifest) |
| Required secrets that should not be supplied by the user | `DPU_MASTER_KEY`, `ONLYOFFICE_JWT_SECRET`, `JWT_SECRET`, WebMeet LiveKit/TURN secrets, Ploinky agent identity secrets, and Soul Gateway signed agent keys are generated or runtime-injected |
| Optional user-provided values | Web Publishing Cloudflare API credentials, external LLM/search provider keys, and non-public WebMeet media/runtime tuning |
| Unknown | Any env requirements from `UmamiAgent/umamiAgent`, because its source was unavailable |

Explorer has a single manifest profile, `default`. That profile enables
`basic/web-publishing` as both a blocking dependency and startup config
provider, so local, QA, and production launches use the same Explorer wiring.
Public browser topology is owned by Web Publishing, which runs before the rest
of the stack publishes dependency env through Ploinky startup config providers.
Existing workspace vars for the old direct OnlyOffice/WebMeet public topology
must be cleared before startup so stale public URLs cannot outrank Web Publishing.
Managed QA/production workflows reject `cloudflare-api`: they do not invoke
external tunnel or DNS mutations. Every accepted public mode preflights the
operator's DNS-only TURN A record, absence of any TURN AAAA record, and remote certificate/key before repository
or startup work; DNS resolution validates both address families but cannot prove the proxy
flag. The same early guard requires `nginx` to use an `external` TLS edge and
all accepted token modes to use a `cloudflare` TLS edge. Before remote mutation,
the workflows also reject non-canonical base domains and non-public-form media or
TURN IPv4 inputs. After startup they require the provider output to equal exactly
`wss://meet.<base-domain>`; they do not reinterpret downgraded signaling schemes.

## Exhaustive Classification

| Classification | Variables | Applies to | User-supplied? | Notes |
| --- | --- | --- | --- | --- |
| Mandatory Web Publishing topology inputs | `WEB_PUBLISHING_BASE_DOMAIN`, `WEB_PUBLISHING_TLS_EDGE`, `WEB_PUBLISHING_LIVEKIT_MEDIA_IP`, `WEB_PUBLISHING_TURN_EXTERNAL_IP` | `basic/web-publishing` | Yes for managed QA/prod public deployments | Generate the `explorer.`, `office.`, `meet.`, and separate `turn.` topology; declare `cloudflare` or `external` trusted WSS termination; and provide independent direct media/TURN IPv4 addresses. Managed workflows require a canonical lowercase DNS domain and bare unicast/non-loopback IPv4 values. |
| Mandatory Web Publishing token-mode tunnel input | `WEB_PUBLISHING_CLOUDFLARED_TUNNEL_TOKEN` | `basic/web-publishing` | Yes when `WEB_PUBLISHING_MODE` is `cloudflare-token`, `token`, or `nginx-cloudflare` | Mapped by the Web Publishing manifest to container env `TUNNEL_TOKEN`. The old unscoped token variable is not a Web Publishing input or output. |
| Mandatory managed-deploy TURN prerequisites | `turn.<WEB_PUBLISHING_BASE_DOMAIN>` DNS-only A record with no AAAA record; `.ploinky/data/webmeetTls/turn/{fullchain,privkey}.pem` in the selected remote workspace | Deployment preflight, then `turnServerAgent` | Yes for managed public deployments | Every resolved A record must equal `WEB_PUBLISHING_TURN_EXTERNAL_IP`, and the IPv4-only hostname must resolve no AAAA addresses. An unexpected AAAA lookup error fails closed. TLS files must be readable regular non-symlink files; the certificate must be unexpired, cover the TURN hostname, and match the private key. The workflow validates but never provisions or mutates these resources. |
| Optional Web Publishing route inputs | `WEB_PUBLISHING_MODE`, `WEB_PUBLISHING_PUBLIC_URL` | `basic/web-publishing` | Optional/defaulted | The Web Publishing mode normalizer selects `nginx` when the mode is unset; the manifest itself declares no default. QA/prod workflows can set another supported mode, for example `nginx-cloudflare`. `WEB_PUBLISHING_PUBLIC_URL` can pin the Explorer callback base URL when it differs from the generated route. Neither is a fallback for the explicit media or TURN IP inputs. |
| Optional Web Publishing Cloudflare API inputs | `WEB_PUBLISHING_CLOUDFLARE_API_TOKEN`, `WEB_PUBLISHING_CLOUDFLARE_ACCOUNT_ID`, `WEB_PUBLISHING_CLOUDFLARE_ZONE_ID`, `WEB_PUBLISHING_CLOUDFLARE_TUNNEL_ID`, `WEB_PUBLISHING_CLOUDFLARE_TUNNEL_NAME` | `basic/web-publishing` dashboard/admin tools | Only when separately using Web Publishing API tooling | Used for explicitly invoked tunnel/DNS planning and apply operations from the Web Publishing settings surface. Managed Explorer workflows reject API mode and never invoke these mutations. |
| Web Publishing provider outputs | `ONLYOFFICE_PUBLIC_URL`, `ONLYOFFICE_INTERNAL_URL`, `ONLYOFFICE_CALLBACK_BASE_URL`, `WEBMEET_PUBLIC_LIVEKIT_URL`, `WEBMEET_LIVEKIT_URL`, `WEBMEET_LIVEKIT_NODE_IP`, `WEBMEET_TURN_HOST`, `WEBMEET_TURN_EXTERNAL_IP`, `WEBMEET_TURN_ALLOWED_PEER_IPS` and declared edge metadata | Explorer, `onlyOffice`, `webmeetAgent`, `webmeetInfra/liveKitServerAgent`, `webmeetInfra/turnServerAgent` | No direct workflow injection | These are written by Ploinky from the Web Publishing provider response before dependent agent env is resolved. Managed deploys require `WEBMEET_PUBLIC_LIVEKIT_URL` to equal exactly `wss://meet.<base-domain>` before probing `/rtc`; no signaling-scheme fallback is permitted. The TURN peer allowlist is the exact LiveKit media address as a `/32`; Coturn derives its realm from the canonical TURN hostname; browser signaling, direct media, and TURN remain separate outputs. Retired `WEBMEET_TLS_HOSTNAME`, `WEBMEET_CERT_EMAIL`, `WEBMEET_LIVEKIT_UPSTREAM`, and `WEBMEET_TURN_REALM` values are not provider outputs. |
| Mandatory user-provided for deployment control, not agent runtime | `PLOINKY_MASTER_KEY` | Ploinky CLI/router/secret store | Yes for managed deployments | This belongs to the launcher/workspace secret store. Agents must not receive it. Keep it stable after first deployment because it decrypts `.ploinky/.secrets` and generated secret material. |
| Mandatory user-provided for remote deploy access, not agent runtime | `SSH_KEY`, `SSH_USER`, `SSH_HOST` | GitHub Actions and remote host access | Yes for remote workflows | These are deployment inputs, not Ploinky agent env vars. |
| Conditional external LLM provider keys | `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `GEMINI_API_KEY`, `XAI_API_KEY`, `OPENCODE_API_KEY` | Achilles CLI family, `webAssist`, direct provider fallbacks | Only when using those providers directly | The intended Explorer stack routes LLM access through the local Soul Gateway and Ploinky signed agent keys. |
| Conditional Soul Gateway provider/search keys | `AXIOLOGIC_PROXY_API_KEY`, `DEFAULT_PROXY_API_KEY`, `OPENROUTER_API_KEY`, `TAVILY_API_KEY`, `BRAVE_API_KEY`, `EXA_API_KEY`, `SERPER_API_KEY`, `JINA_API_KEY`, `SEARCH_TAVILY_API_KEY`, `SEARCH_BRAVE_API_KEY`, `SEARCH_EXA_API_KEY`, `SEARCH_SERPER_API_KEY`, `SEARCH_JINA_API_KEY`, `SEARCH_SEARXNG_BASE_URL` | `proxies/soul-gateway`, search tooling | Only when enabling those external integrations | Some manifests and code use different names for search provider keys. Treat both forms as optional external-provider configuration. |
| WebMeet private runtime tuning | `WEBMEET_LIVEKIT_LOG_LEVEL`, `WEBMEET_LIVEKIT_FORCE_TCP`, `WEBMEET_LIVEKIT_REDIS_ADDRESS`, `WEBMEET_EGRESS_REDIS_ADDRESS`, `WEBMEET_LIVEKIT_INTERNAL_WS_URL`, `WEBMEET_ICE_TRANSPORT_POLICY` | WebMeet agents and LiveKit infra | Optional/defaulted | Public signaling/media/TURN topology is generated by Web Publishing. Relay ranges, quotas, and lifetimes use the hardened infra-manifest defaults rather than deployment-workflow overrides. `WEBMEET_ICE_TRANSPORT_POLICY` must be exactly `all` or `relay`. |
| Possible config gap | `WORKSPACE_PATH` | `AchillesCLI/GPTResearcher` install script | Runtime/workspace should provide it | The install hook requires it. If Ploinky does not provide it, the operator may need to set it. |
| System/runtime defaults | `HOME`, `PATH`, `SHELL`, `PORT`, `HOST` | Several agents | No | Supplied by OS/container/runtime or manifest defaults. |
| Required generated DPU secret | `DPU_MASTER_KEY` | `dpuAgent` | No | Generated from manifest runtime resources. The DPU store requires it, but the user should not provide it. |
| Required generated OnlyOffice secrets | `ONLYOFFICE_JWT_SECRET`, `JWT_SECRET` | Explorer and `onlyOffice` | No | Shared generated secret. `JWT_SECRET` maps to the same value for the Document Server. |
| Required generated WebMeet secrets | `WEBMEET_LIVEKIT_API_KEY`, `WEBMEET_LIVEKIT_API_SECRET`, `WEBMEET_TURN_AUTH_SECRET`, `PLOINKY_WEBMEET_MASTER_KEY` | `webmeetAgent`, `webmeetInfra/liveKitServerAgent`, `webmeetInfra/turnServerAgent` | No | Shared/generated secrets. The TURN REST secret is shared only by LiveKit and Coturn; `webmeetAgent` never receives it. |
| Generated or signed gateway credentials | `SOUL_GATEWAY_API_KEY`, `PLOINKY_AGENT_API_KEY`, `PLOINKY_AGENT_API_PUBLIC_KEY` | Soul Gateway consumers and `proxies/soul-gateway` | No | Modern Explorer should use Ploinky signed subject credentials for the local Soul Gateway. |
| Ploinky agent identity | `PLOINKY_AGENT_ID`, `PLOINKY_AGENT_SECRET`, `PLOINKY_AGENT_PRINCIPAL` | All agent-to-agent and router-mediated calls | No | Injected by Ploinky. Agents must receive only their own identity secret. |
| Ploinky router/workspace env | `PLOINKY_ROUTER_URL`, `PLOINKY_ROUTER_HOST`, `PLOINKY_ROUTER_PORT`, `PLOINKY_WORKSPACE_ROOT`, `PLOINKY_PROFILE`, `PLOINKY_RUNTIME`, `PLOINKY_SHARED_DIR`, `PLOINKY_CWD`, `PLOINKY_AGENT_LIB_DIR`, `PLOINKY_INVOCATION_AUTH_MODULE` | Many agents | No | Runtime-injected values used for routing, workspace discovery, and secure-wire invocation. |
| Ploinky master/derived internals | `PLOINKY_MASTER_KEY`, `PLOINKY_DERIVED_MASTER_KEY`, `PLOINKY_ENV_SOURCE_*` | Ploinky launcher/router/secret resolution | No for agents | `PLOINKY_MASTER_KEY` may be supplied to the Ploinky CLI, but must not be injected into agents. |
| Workspace root overrides | `ASSISTOS_FS_ROOT`, `WORKSPACE_ROOT`, `DPU_DATA_ROOT`, `DPU_WORKSPACE_ROOT`, `MCP_FS_ROOT`, `LOCK_FOLDER` | Explorer, DPU, tasks, WebMeet | No in normal launch | Ploinky/workflow sets roots. Operators may override for nonstandard layouts. |
| Explorer optional config | `AXIFACE_REPO_PATH`, `AXIFACE_REPO_URL`, `SOUL_GATEWAY_BASE_URL`, `FS_CACHE_TTL_MS`, `LLM_AUTOCOMPLETE_DEBUG` | Explorer | Optional | Tuning and integration overrides. Public OnlyOffice callback/public URLs come from Web Publishing through Explorer's default profile. |
| Unknown | Unknown | `UmamiAgent/umamiAgent` | Unknown | The Explorer manifest enables this agent, but no source was available in this workspace. |
