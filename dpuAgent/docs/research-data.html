Research Data and Controlled Processing

The DPU registers exact, attributable research resources and mediates Hugging Face acquisition and EDC negotiation or transfer.

Flow

Discover → inspect facts and policy → confirm external effects → run an actor-scoped idempotent job → stream and verify revision/checksums → atomically publish local data → append provenance.

Explorer

Research Data and Jobs are virtual records, not ordinary folders. The standard Tools menu opens DPU Research WebChat even when Research Data is empty. Resource previews expose acquisition, access request, sharing, permission, provenance, and DPU Agent actions. The runtime plugin reuses Explorer cards, buttons, status badges, action groups, standard confirmation and permission modals, settings tabs, fullscreen control, and custom-select. Local CSS is limited to DPU-specific structure and responsive layout. Data Sources presents separate Hugging Face and EDC panels with provider-specific inline add and edit forms inside a stable-size, internally scrolling dialog. Administrators configure only the implemented connection fields and select a DPU secret reference; the active panel fixes the provider type, and credential values are never copied into source state.

The WebChat entry point reads each router envelope as soon as it arrives on the persistent runtime pipe. It verifies the envelope-bound router request, derives the actor without exposing the token to the model, and gives the planner the exact DPU tool catalog from mcp-config.json. Planner calls and MCP calls share the same validation, authorization, audit and domain dispatch. DPU tool decisions use the Achilles Markdown envelope, and the prompt section must contain exactly one fenced json block with one schema-valid object and no surrounding prose. Raw JSON, malformed JSON, arrays and untyped fences fail closed. Exact DPU source UUIDs must come from DPU results; provider types and display names are rejected as substitutes. A rejected planner payload is returned as a structured recoverable result so the next decision receives the validation reason and bounded retry instructions; invalid source labels are removed rather than interpreted as IDs, and the rejected call performs no provider operation. The entry point handles the internal /tasks discovery command locally with an empty task list and never forwards slash commands to the research LLM. Presentation visibility is preserved, and a request failure is isolated so later messages remain usable. It does not wait for the pipe to close between messages; end-of-file input is reserved for one-shot CLI and MCP calls.

Security boundary

Explorer is presentation only. Actor identity and invocation scope come from verified authentication, credentials come from DPU secrets, and provider policy remains authoritative. Physical storage paths are not returned to clients.

Execution Boundary

Secure and federated records can be represented. Execution requires a configured backend that supplies trusted confirmation, attestation, policy, and participant-resource verification; without that evidence the operation fails closed.
