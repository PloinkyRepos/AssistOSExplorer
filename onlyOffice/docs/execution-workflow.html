Documentation / Execution workflow

Execution Workflow

An authenticated Explorer request creates a bounded editor session; the public proxy then carries only validated editor traffic and signed callbacks for that session.

Session And Editor Flow

Session State

Session creation resolves the current immutable topology generation and stores an atomic, guarded 0600 state file under the persistent work directory. Each session receives its own document key and callback URL. Configuration and callback tokens are short-lived, body-bound JSON Web Tokens.

Callbacks And Recovery

The callback storage service authenticates its own token before using claims, rejects malformed or duplicated forwarding fields, enforces body limits, and persists document changes through the selected workspace or delegated DPU store. Restart recovery drains active sessions, persists their state, and reopens only after the replacement topology generation is ready.
